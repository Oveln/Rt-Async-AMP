# K3 IPC 延迟归因与优化总结报告

**时间跨度**：2026-08-16 → 08-23（八天，约 20 轮板上测量）
**对象**：K3 COM260 真板，AP（X100 大核，StarryOS/Linux）↔ RP（RT24 小核 @~246MHz，rt-async RTOS）跨核 RPC
**结果**：单条 PING 往返 **294µs → 236.9µs（−19.5%）**；顺带挖出并闭环一个正确性暗雷（A4：cbo.flush 静默丢发布，见附录 B）

## 0. 一页总结

**一句话讲完全程**：跨核 RPC 慢，不是慢在协议和数据搬运，而是慢在两笔"隐形税"——
**内存序 fence**（每条 ~2.2µs，一条消息要付 ~14 笔 ≈ 31µs）和**计时器冷读**
（mtime 只要隔一小段再读就要 24.5µs，是跨时钟域同步器重新锁定）。对症下药砍 fence
笔数（P3 ✅），换计时器两度尝试两度证伪（那笔冷读税在真实路径上根本没被付过），
再用看门狗兜住优化过程中发现的一个缓存写回丢失 bug（A4 ✅）。

```text
以 P1 后的 240µs 基线分解（P3 后实测 236.9µs，构成相同）：
   AP 发送 8.5  →  门铃+唤醒链 ~40  →  RP 取包+分发 ~75  →  响应+门铃 ~20
   →  AP 收到 25  →  其中 ~50µs 是"读自己计时器"和"内存序 fence"的隐形税
```

**三大发现**（决定了整个优化路线）：

| # | 发现 | 实测 | 影响 |
|---|------|------|------|
| 1 | **fence 恒定 2.2µs/条**（`ld+fence r,rw` 即 Acquire 读） | 四种口径全 2198-2222ns | 每条消息热路径 ~14 条 fence ≈ 31µs；这是**内存序的物理税**，只能靠减少笔数 |
| 2 | **mtime 计时器冷读 24µs/笔**（间隔 >15µs 后跨时钟域同步器重锁） | 热循环 106ns → 间隔 20µs 后 24.5µs（231 倍）；mcycle CSR 冷读更慢（~2.9ms；热读仅 17ns、按核频 245.84MHz 计数） | 每条消息的计时/统计链吃掉 24-48µs（生产构建）或 40-70µs（测量构建）——**既是真执行税，也污染了所有分段测量** |
| 3 | **W2 双向轮询实测 −11µs**（AP 响应方向改用户态自旋，免 syscall/内核唤醒） | rtt 189→178，零固件改动 | 路线图里最便宜的一步，已经预演成功 |

**优化记分牌**（详见 §6，图 5）：

| 项 | 结果 |
|----|------|
| P1 本地原子 + timer 直连 + 别名窗 + mailbox 去 Acquire | ✅ rtt 294→240 / D2 209→189 |
| P3 fence 去冗余 | ✅ 同启动 A/B −10µs（246.9→236.9），自旋 18→9.4µs/轮 |
| 计时瘦身·换源（counter1 / AON_TIMER1 两个候选） | ❌ 两度板上证伪并回滚；定案：计时源生产中性 |
| P2 ISR 直派 | ❌ 用户否决：不破坏 rt-async 任务模型 |
| A4 正确性修复（cbo.flush 静默丢发布） | ✅ 四代弧线闭环（附录 B） |
| W2 双向轮询产品化 | ⏳ 下一刀，已预演 −11µs |

### 名词速查（第一次读先看这里）

| 术语 | 意思 |
|------|------|
| AP / RP | 大核 X100（跑 Linux）／小核 RT24（跑 rt-async RTOS） |
| rtt | 一条 PING 请求的完整往返时间 |
| D1 / D2 / D3 / D4 | RP 发现请求的四种路径：D1 门铃唤醒（间隔 >2s）/ D2 弹性自旋命中（<2s，免门铃免 syscall）/ D3 批处理追加 / D4 竞态闭环兜底 |
| W | RP 的弹性自旋窗口时长（实测 ~2s）：发送间隔短于它就走 D2 免门铃 |
| send | AP 用户态写请求 + 发布缓存 的耗时 |
| ddrain / ddisp | RP 中断服务里的 mailbox 排空 ／ trap 返回 + 调度 + 执行器派发 |
| dseen | RP 任务恢复 → handler 入口的总段，细分为 dpre（弹性前缀）/ drx（try_recv 取包）/ dserde（分发+反序列化） |
| didx / dslot / drest | 更细的探针分段：索引读取 ／ 消息槽读取 ／ dispatch 宏+postcard |
| S / APret | S = 去程门铃 + RP 服务尾 + 响应门铃（钟差无关量）；APret = AP 从收到 IRQ 到用户态读完响应 |
| fence / Acquire / Release | RISC-V 内存序指令；RP 上一条 Acquire 读 ≈ 一次 fence ≈ 2.2µs |
| SPSC | 单生产者单消费者环形队列（ov-channels 通道结构：magic 头 + 读/写索引 + 128×256B 消息槽） |
| CBO / user-cbo | Zicbom 缓存维护指令（flush=写回脏行、inval=作废驻留副本）；user-cbo = AP 用户态按行自做缓存维护、跳过内核整窗刷 |
| mtime / mcycle / counter1 / AON_TIMER1 | 四个候选计时器：mtime（SoC 共享块，跨域）/ mcycle（CSR，核频）/ counter1（AP 域 APB）/ AON_TIMER1（RP 本地域） |
| stamps | 测量构建（probe feature）在 RPC 各阶段打的 mtime 时间戳 |
| 闭环残差 | `rtt` 与各分段之和的差，应恒为 0——用于证明整套测量自洽 |
| 探针税 ≠ 生产税 | 探针（隔离微基准）量到的价格不等于真实路径上的价格——本次工作最重要的方法学教训之一 |
| 同启动 A/B | dd 数据只在同一次开机内可比——跨启动有环境态漂移（见 §6.2） |

## 1. 系统与一条消息的旅程

```
┌─────────┐   写请求槽+索引       ┌──────────────┐    读槽+分发+响应
│ AP 大核  │ ──cbo发布──▶ 共享窗  │ ◀──────────  │  RP 小核 rt-async
│ Linux   │   SRAM 100KB         │   弹性自旋/IRQ │  614/491MHz RTOS
└────┬────┘                      └──────────────┘
     │  ▲ mailbox 门铃（硬件 FIFO，IRQ 3463ns/次）
     ▼  │
   AWAIT ioctl（内核睡眠等响应）
```

- **通道结构**（ov-channels SPSC 环）：ch0 请求（AP→RP）、ch1 响应（RP→AP）、ch2 急停。每通道 = magic 头 + 读写索引（同 cache line）+ 128×256B 消息槽。
- **四种发现路径**：D1 门铃唤醒（间隔 >2s）/ D2 弹性自旋命中（<2s，免门铃免 syscall）/ D3 批处理追加 / D4 竞态闭环兜底。
- X100 的共享窗映射**实际 cacheable**（PTE PBMT 不生效），跨核一致性全靠 fence/CBO 同步点——这是一切 fence 税的根源，也是附录 B 正确性 bug 的根源。

## 2. 总预算：240µs 花在哪了（图 1）

![图1](01_budget_waterfall.png)

D1 路径六段（dd 场景闭环恒等式 `rtt = send + ddrain + ddisp + dseen + S + APret`，残差 0.0）：

| 段 | 含义 | 实测 µs | 内部构成 |
|---|------|-------|---------|
| send | AP 用户态写入+发布 | 8.5 | user-cbo 按行发布（槽 4 行+索引 1 行）+ BUSY 判定，D2 路径零 syscall |
| ddrain | RP ISR 舞步 | 3.6 | mailbox FIFO 排空 + latch（①′优化后从 11.3 降来） |
| ddisp | trap+调度+MSIP 落地 | 27.1 | 含 MSIP 跨桥写落地 ~54µs 物理地板的摊派 + 执行器派发（ISR 直派已否决——处理留 task 上下文，此段为 rt-async 任务模型的结构性成本） |
| dpre | 发现前缀 | 24.3 | set_busy(2.2) + ch2 空查(6.6) + **mtime 戳税(~14)** + 链路 |
| drx | try_recv 取包 | 45.6 | 3 笔 Acquire(6.6) + 槽读(1.2) + Release(2.2) + **mtime 戳税(~24)** ≈ 真实 ~20 |
| dserde | 分发+反序列化 | 38.0 | method_id(1.1) + dispatch/postcard(~10) + **mtime 戳税(~24)** ≈ 真实 ~11 |
| S | 服务尾+响应+回程门铃 | 67.7 | handler 余下 + 响应 try_send(16.6) + notify(3.4) + AP 内核唤醒 Y≈54(物理地板) |
| APret | AP 唤醒回收 | 25.3 | IRQ→调度→用户态→读响应 |

**怎么读这张表**：dpre/drx/dserde 是"含计时戳税的测量值"——每段边界那笔 mtime 读因为和上
一笔隔了一小段，吃的是 24.5µs 冷价而非 106ns 热价。剥掉戳税后的 RP 真实执行见 §4 图 3。
**D2 路径**（189µs）：send 8.8 + 自旋发现（半周期 ~9µs）+ RP 真实处理 ~70-90 + AP 收尾——
同样的 RP 账本，只是唤醒链换成了轮询粒度。

## 3. 每种操作的实测单价（图 2）

![图2](02_op_unit_price.png)

### 3.1 数据搬运（裸访存，无内存序）——都很便宜

| 操作 | 单价 | 说明 |
|------|------|------|
| 裸读 SRAM 同址 | 22ns | 前端合并效应（连续读同地址被合并） |
| 裸读 SRAM 顺序跨行 | 195ns | 流水后 |
| 裸读 SRAM 冷跨行（512B 步进） | 417-520ns | 无流水 |
| **256B 消息槽整块读** | **1.2µs** | try_recv 的取包成本 |
| **256B 消息槽整块写** | **6.3µs** | 写穿无合并（send_seq 推出）——写比读贵 5 倍 |
| mailbox 寄存器读 | 148-196ns | 主域窗口 148 / 本地窗口 180 |

### 3.2 内存序（fence）——核心税 #1

| 操作 | 单价 | 生成物 |
|------|------|--------|
| Acquire 原子读 | **2198ns** | `ld` + `fence r,rw`（从来不是原子指令！） |
| Release 原子写 | **2222ns** | `fence rw,w` + `sd` |
| 纯 fence | ~2095ns | 四变体（r,rw / rw,w / rw,rw / iorw,iorw）全同价 |
| 本地原子 RMW（P1 CS 后端） | **~90ns** | `csrrci mstatus,8` + 普通 ld/sd，P1 战果 |

**规律**：fence 与冷热、地址、目标（SHM/本地 .bss）**全部无关**，恒定 2.1-2.2µs。RP 对窗口无缓存（读到即真值），但免 fence 的纯读会被前端合并缓冲**钉死陈旧值**（litmus L1：0/200 新鲜）——所以跨核读必须付 fence，没有免费刷新原语（邻址读、CBO 替代均无效/未证）。

### 3.3 计时器——核心税 #2（本次工作最大意外）

| 操作 | 单价 | 说明 |
|------|------|------|
| mtime MMIO 读（热循环） | 106ns | 背靠背流水价 |
| **mtime MMIO 读（非背靠背）** | **~24.5µs** | 跨时钟域同步器重锁，231 倍；**任意非背靠背间隔触发**（poll 间隔几十 ns 亦冷——now_gapped 每轮 69µs，见 §6.8） |
| mcycle CSR 读（热） | **17ns** | 4 cycle/笔，CSR 本地读无 MMIO |
| mcycle CSR 读（间隔 ~400µs） | **~2.9ms** | 冷读税比 mtime 重 118 倍；但计数为**核频 245.84MHz**（cycle_cal 联标 1,229,222c/5ms，非 mtime 同源）——"仅冷读慢"型：测量 stamp 链可迁 mcycle+段间保温（保温笔 17ns），生产每消息级间隔计时不可用 |
| **soc-timer counter1（0xd4016094）** | 背靠背 277ns；**间隔读 ~13µs** | AP 域 APB 块，12.8MHz 自由运行（mux=0）。换源**板上证伪**（08-22，6f4ec9d 回滚）：277ns 是流水价，真实路径 mark 间隔 µs 级仍触发 ~13µs 重锁税，整链 8 笔净亏（rtt 240→248.5 实证）；驱动已删（dfb8b5e，timer_k3 改道本地域） |
| **AON_TIMER1（0xc0889000，本地域）** | 背靠背 **4ns**；纯本地间隔读 **~1.9µs**；生产路径间隔读 ~10µs 级 | RCPU AON 域专属。板上验证：计数递增、实测 **2.0001MHz**（文档标称 SEL=0=25.6MHz 与实况不符）。**生产迁移二度证伪回滚（05691b0）**——探针税 ≠ 生产税，见 §6.2 |

**推论**：每条消息的计时/统计链（step 计时、SVC 统计、弹性窗计时、测量构建的 stamp 链）里有若干笔"间隔上百 ms 的冷读"——**每笔真等 24µs**。测量构建每消息 6-8 笔（40-70µs 税）；生产构建只剩 2-4 笔（24-48µs 税）。

### 3.4 门铃/中断与计算

| 操作 | 单价 |
|------|------|
| 门铃 notify（fence + mailbox MMIO 写） | 3.46µs |
| postcard 构+解双向（PING 形状） | 9.4µs |
| dispatch 全程（宏 match+反序列化+handler+响应构造） | 18.2µs（op 内热价） |
| MSIP 跨桥写落地 | ~54µs（物理地板，rtbench sec8 定案） |

## 4. RP 侧每条消息的逐笔账本（图 3）

![图3](03_rp_message_budget.png)

**左柱：测量构建的实测三段（108µs）**——每段混入段边界那笔 mtime 冷读（~24µs/笔）。
**中柱：剥离后的真实执行（~91µs）**，逐笔账：

| 环节 | 操作序列 | 笔数 | 小计 |
|------|---------|------|------|
| 弹性前缀 | set_busy(Release 2.2) + ch2 空查(3×Acquire 6.6) + 链路 | 4 fence | ~11µs |
| **取包 try_recv** | magic Acq + read Acq + write Acq + 槽读 1.2 + read Rel | **4 fence + 1 块读** | **~20µs** |
| 分发 | method_id + 宏 match + postcard 反序列化 | 纯计算 | ~11µs |
| **响应 try_send** | magic Acq + write Acq + read Acq + 槽写 6.3 + write Rel | **4 fence + 1 块写** | **~15µs** |
| 回门铃 | notify = fence + MMIO 写 | 1 | 3.4µs |
| 收尾 ch2 再查 | 3×Acquire | 3 fence | 6.6µs |
| 生产计时税 | step/SVC 计时 1-2 笔冷 mtime | 1-2 | ~24µs |
| **合计** | | **~14 fence** | **~91µs** |

其中**结构性冗余**（P3 的靶子）：magic 每次都查（运行期不变）、read/write 索引里有一半是"自产数据"（RP 是唯一写者，免 fence 即新鲜）、ch2 前后两次全量查。
**右柱：P3 当时的理论目标 ~42µs**——实际兑现：didx 7.6→3.1µs（3→1 笔 Acquire 精确兑现）、消息级 −10µs、自旋 18→9.4µs/轮（§6.3）。

## 5. 侦探故事：九个假设与一个真凶（图 4）

![图4](04_mtime_trap.png)

32µs 级缺口（探针合计解释不了的 drx/dserde 超额）排查了九个假设：

| 假设 | 判定实验 | 结果 |
|------|---------|------|
| H1 fence 冷热单价差异 | aq 四口径（同址热/跨址/间隔/本地） | ✗ 全部 2198-2215ns |
| H2 postcard 反序列化慢 | postcard_rt | ✗ 双向才 9.4µs |
| H4 WFI 冷核执行惩罚 | dd 100ms 间隔（D2 热态） | ✗ svc/drx 与 D1 冷态同价 |
| H5 真实通道地址溢价 | self_round（真实 ch0 自往返） | ✗ = scratch 复刻之和（差 1%） |
| H7 冷取指/冷执行 | dd warm_gap（测量前 300µs 预热同路径） | ✗ drx 43.7 纹丝不动 |
| H8 新鲜写落地延迟 | fresh 衰减扫描（D: 0→50ms） | ✗ 仅 11.4µs@D=0 且大半是戳假象 |
| H9 AP 内核活动竞争 | spin-await（AP 零 syscall 零调度） | ✗ drx 仍 43.5；**附产物：W2 实测 −11µs** |
| **终案：mtime 冷读** | **now_gapped** | ✓ 间隔 20µs 单笔 24.5µs，同时解释 dslot 37.2（=槽读 12+戳 24）/ drest 34.0（=dispatch 10+戳 24）/ didx 7.8 干净（间隔 8µs 未过阈值）的全部对称性 |

讲解动线：*"同一操作，探针 11.7µs、真实路径 43.6µs、预热也不降、AP 睡死也不降——那慢的必然在 RP 内部且与'相邻两次计时器的间隔'有关。now_gapped 一锤定音。"*

**附：过程中意外修出的三个潜伏 bug**（详见附录 A）：槽区布局偏移错 0xF0（sizeof 断言无法区分）、AP 按行刷新错位（靠内核兜底而虚标）、`csrr cycle` 在 M 态未实现（Illegal Instruction）。

叠加预期（不含已否决/已证伪项）：**D1 240→230（P3 已验收）→~219（W2 后），D2 189→~179→~168**。再往下就是 SPSC 协议本体（每消息 4 笔 fence ≈ 8.8µs）+ 数据搬运（~7.5µs）+ 任务模型结构性成本（ddisp ~27µs）的物理下限区。

### 6.1 P1 ✅：本地原子 + 去外域（294→240）

K3 专属 target（`atomic-cas:false`）让本地原子（计数器/状态机/IrqLatch）落入单核
critical-section 后端（mstatus MIE 屏蔽 ~90ns/笔，替代 Atomics Wrapper 序列化的
2.2µs）；timer clint 直连 + 共享窗本地别名（DTS reg=0x0）+ mailbox 驱动去 Acquire。
板上验收（08-20）：rtt 276.1→240.0，最大头 ddisp 56.7→27.1（"MSIP 落地 54µs"假设
同时证伪——唤醒链大头其实是本地原子税）；D2 209→189。跨核窗口原子保持 core 原生
（ov-channels [patch.crates-io] 引用，正确性关键）。

### 6.2 换源 ❌：两度证伪与"环境态"定案（方法学最重要的一课）

**counter1 轮（08-21 判可行 → 08-22 板上证伪）**：探针全绿（12.8MHz 自由运行、热读
277ns）→ 迁移 → rtt 240.0→248.5 反向。归因：277ns 是背靠背流水价，真实路径 stamp
间隔 µs 级时每笔 ~13µs 重锁税（12.8MHz 计数钟到 RCPU 总线同样跨时钟域，病轻于
mtime 但整链 8 笔净亏）。已回滚（6f4ec9d），驱动删除（dfb8b5e）。
**AON_TIMER1 轮（08-22）**：本地域新候选，探针达标（实测 2.0001MHz、热读 4ns 全系统
最快、纯本地间隔读税 ~1.9µs）→ 迁移（eb2da18）→ rtt 251.5"更差"→ 回滚复测
（mtime 版固件）rtt 仍 ~249——与 counter1 轮（248.5）/AON 轮（251.5）**三轮统计
同形 ⇒ 修正定案：+11µs 全部为启动间环境态漂移**（send 8.5→14.4 三轮恒定佐证），
**计时源在生产路径是中性的**——mtime 24.5µs 冷读税在真实路径被交织的 SHM/fence
流量保温从未支付（无税可省），替换计时器也无额外代价。回滚（05691b0），换源线关闭。

两条固化规则：
- **探针税 ≠ 生产税**——探针只作筛选，优化验收只认生产 dd；
- **dd 对比只认同一次启动内的 A/B**——跨启动环境态漂移（send 段 +6、RP 段 +5，
  同启动内极稳 σ=0.16µs；疑热态/频率/加载地址类因素，未解挂账）。

timer_k3 驱动与 tmr_aon_* 探针保留：AON_TIMER1 本身是真发现（活本地域 2MHz 计数器，
短间隔测量备用）。

### 6.3 P3 ✅：fence 去冗余（−10µs/消息，08-22 08:11 轮验收）

SPSC 单写者论证下把**结构性冗余的 fence 降级**：magic → Relaxed（运行期不变量，
mapping 建立屏障已覆盖）、自产索引 → Relaxed（RP 是唯一写者，免 fence 即新鲜）；
**对端索引 Acquire 与发布 Release 原样保留——数据可见性协议零妥协**。

验收数据：didx 7.6→3.1µs（σ=0.02，3→1 笔 Acquire 精确兑现）、drx 48.2→43.5、
dpre 25.1→20.6、**同启动 A/B（send≈14.5 环境态系）rtt 246.9→236.9（−10.0µs）**、
自旋 18→9.4µs/轮（spin_iter 17997→9420ns，D2 收益）。实现位于 ov-channels
b45bc0a + ov-rpc stamps 对齐（508be4b）+ 主仓指针（bd662e7）。
中间弯路：ov-rpc server.rs 的 stamps 手写展开取包序列是 ov-channels 的逐笔复刻，
改内存序必须双处同步（首轮漏对齐致 didx 不动，已修）。

### 6.4 A4 ✅：正确性修复（详见附录 B）

优化过程中发现的 X100 cbo.flush 静默丢发布（AP 写的环索引偶发永远到不了 SRAM，
RP 视而不见 → 消息丢失 → 挂死）。四代弧线：同核回读检测证伪 → 纯重发被"粘滞"
证伪 → **重写同值造新脏行再发布**（republish）破粘滞 → v2 封掉回卷地雷。终验
（08-23 04:19 轮）：fresh_scan 全绿、mb 无幻影消息、dd 零代价（rtt 237.7 ≈ 236.9
基线、闭环残差 0.0/30）。恢复机制现于 bench 看门狗，产品化收口随 W2。

### 6.5 W2 ⏳：双向轮询（下一刀）

AP 响应方向改用户态自旋（免 AWAIT syscall/内核唤醒），spin_await 预演已实测
rtt 189→178（零固件改动）。代价是烧 AP 核——作为延迟关键模式提供。恢复逻辑
（A4 看门狗）届时收口进轮询回路的软期限。

### 6.6 P2 ❌ 已否决 + 远期硬件

P2（响应在 ISR 内写完）否决（2026-08-21）：不破坏 rt-async 的任务模型——实际处理
必须留在 task 上下文（executor/waker 语义），ISR 只做唤醒/标记；ddisp 27.1µs 作为
结构性成本保留。远期：mailbox 载荷直传小消息（数据进门铃）、硬件 spinlock
（0xCAC9_1C00，手册背书）。

### 6.7 本地域优先原则（2026-08-22 定案，后续外设选型遵守）

RT24 高延迟访问的根因是**跨簇间互连**——mtime（SysTimer @0xe4000000）虽是 rcpu1
功能上的计时器（mtimecmp 按 hart<<27 分区），但物理上是全 SoC 共享块挂在簇间互连上，
读它必出远门（24.5µs 间隔重锁税即互连/桥的空闲路径唤醒；热读 106ns 证明路径本身
不慢；机制无文档，未解项）。**RT24 本地总线上的外设只有 0xc088_xxxx AON 域这批**
（06_address_map §6.2：AON_TIMER1~4、mailbox、PWM 等）。凡是高频访问的外设
（计时、自旋索引），尽可能以本地域替代外域。
附带破案：**"rtimer0 块死"悬案**——非域过滤，是 `MCU_TIMER1_CLK_RST`（0xc088c04c）
bit0 TIMER_SW_RSTN **低有效**（复位值 0=保持复位），当时按 APBC 高有效惯例写两笔
0x7→0x3，第二笔清了 bit0 把外设重新按住复位。

### 6.8 计时器专题附记

- **mcycle 三面定案**（08-21 板上）：热读 17ns（4 cycle，CSR 本地）、频率
  **245.84MHz = 核频**（≈491.52/2；此前"与 mtime 同源 24MHz"证伪）、间隔读
  ~2.9ms（比 mtime 重 118 倍）——"仅冷读慢"型：测量 stamp 链可迁 mcycle+段间保温
  （保温笔 17ns），生产每消息级间隔计时不可用冷读。
- **mtime 税模型再修正**：now_gapped 69µs/轮（t0 + 首笔 poll 都吃 24.5µs 冷价）
  证明 **mtime 冷读由"任意非背靠背间隔"触发**（poll 间隔几十 ns 亦冷）；而
  tmr_gapped 在 t1 前插入一笔异设备读（counter1 277ns）后每轮仅 22.4µs——mtime
  读全部变热。机制未解（流水线/前端行为），好奇心探针留给后续。

## 7. 测量方法与可信度

- **dd 场景**：AP 双钟戳（内核 RD_KTS）× RP mtime 戳交叉，钟差无关恒等式（S 与 AP 回程），闭环残差 30/30 = 0.0。
- **mb 场景**：MEMBENCH RPC 35 个微基准 op，热循环 + 间隔变体 + 真实通道自往返。
- **litmus L1/L2/L3**：免 fence 顺序性的正反对照实验，全绿。
- **已知测量坑**（本文已修正/标注）：mtime 戳税污染分段、T_SCHED 连续流不刷新（D2 下 dpre/dseen 失效）、fresh_scan 列错位、判读 g() 索引差一。
- **规则**：探针税 ≠ 生产税（§6.2）；dd 对比只认同一次启动内 A/B（§6.2）。
- **未修已知问题（挂账）**：AP 侧退出段错误（0xffffff00 前缀 EXECUTE，每场景开头/退出各一次，数据有效）；SIGALRM 打不断内核 AWAIT（bench 以心跳看门狗+SIGALRM 兜底）；send 段启动间漂移悬案（§6.2）；s4/s6 回归未跑（P3 改内存序后建议补）。

## 附录 A：过程中意外修出的三个潜伏 bug

1. **槽区布局偏移错 0xF0**：`Message` 是 `align(256)`，`RingBuffer.buffer` 垫到 +0x100 而非朴素假设的 +0x10；sizeof 断言对两种布局同取整（0x8100）无法区分。修复：`ov_channels::RB_SLOTS_OFF` 作为布局唯一真相源 + host 回归单测。
2. **AP 按行缓存刷新错位**（user-cbo `refresh_slot` 用了错的 SLOTS_OFF）：错位 0xF0 期间全靠内核 AWAIT 的 invalidate 兜底——"按行精确刷新"的优化贡献此前虚标。随 1 一并修复。
3. **`csrr cycle` 在 M 态未实现**：用户态别名 CSR 触发 Illegal Instruction 打挂固件；改用 `mcycle`（0xB00）。

## 附录 B：A4 专案——cbo.flush 静默丢发布（四代弧线，08-21 → 08-23）

### B.1 案发与定案（08-21 夜）

fresh_scan 探针（控制"AP 写入 dummy 消息"与"RP 自旋收取"的间隔 D）发现：D=100µs 档
的 dummy 消息 RP 200ms 都看不见，三轮确定性复现。决定性数据：超时时 **AP 缓存视角
发布后 (r=118, w=120)，SRAM/RP 视角仍 (119,119)**——AP 对索引行执行的
`publish`（fence → cbo.flush → fence）没有把新 write 值写回 SRAM。非"同行回卷"分支。
这是 user-cbo 发布链的**真实正确性缺口**：X100 U 态 cbo.flush 对在途 store 存在
静默丢失窗口（疑 store 尚在写缓冲时 flush 清洗到的是旧行）。08-22 13:09 轮生产路径
首次命中：寄存器探测 rd#44 杂散 Notification → 空唤醒 → 强刷后仍空 → 挂死（丢的是
AP→RP 请求索引——RP 从未见请求，回包自然永不到）。

### B.2 一代：发布后回读校验 → 板上证伪（08-22）

`publish_verified`（56c79da）：索引发布点 publish 后 refresh（clean+invalidate）再
从 SRAM 回读比对，不符重试 ×4。**itb f6fc7682 轮证伪**：fresh_scan D=100µs 仍丢。
机制结论：**同核回读由 L1/L2 服务、恒见新值——校验恒通过、重试从未触发，检测等于
不存在**。flush+clean-inval 组合既已失效，双遍 flush 等 CBO 重试族同样无依据（重发
与检测同一视角）；内核 S 态 flush 亦不天然免疫（同一 CBO 指令、PBMT 不生效无 NC
视角可借）。

### B.3 二代：在途看门狗纯重发 → "粘滞"证伪（08-23 01:23 轮）

唯一可信视角是**时间**：请求发出 3ms（rtt 的 >10 倍余量）未见响应即疑似丢失，
幂等重发布（refresh_before_send + publish_send）+ 视 BUSY 补门铃，1ms 连续重试
（b95e950/894f358）。幂等安全性：单请求在途协议下，重发时索引行要么干净（no-op）
要么脏（发布必未落地 ⇒ RP 未消费 ⇒ 行内 read 与 RP 一致）——无回卷窗口；恢复线程
与主线程发送段经 ROUND_LOCK 互斥（封闭"已写槽未发布"期间索引被提前冲出的乱序窗口）。

板上结果：看门狗机制面正常（mb 全套跑完、无挂死），但主使命失败——**D=100µs 丢发布
经 ~200 次重发仍不落地**（RP 整个 200ms 自旋期全盲）⇒ 丢发布行对 AP 侧重复 CBO 呈
**粘滞**，"重试收敛"证伪。关键线索：紧邻的 D=300µs（含**新 store** 的正常发送）
立即成功 ⇒ 粘滞态绑定旧 store 留下的行状态，**新 store 可破**。

### B.4 三代：重写同值再发布 → 验收通过（08-23 04:06 轮）

`cache::republish`（86bc6fe）：索引字段按缓存视图**重写同值**（造出新脏行）→ 标准
发布（槽先于索引）。看门狗节拍改指数退避（1→64ms——二代对合法长 op 每 ms 误报，
5s 级 gapped 计时 op 误触发 ~9000 次）+ guard Drop 逐轮收口打印恢重发次数（二代全局限
流打印 + 双流交错把关键证据藏掉，收口行与超时行直接对账）。

验收：fresh_scan **全 8 档 got=1**——D=100µs 历史三连丢点转收取（7.4µs，收口行
"恢重发 1 次"证明恢复在位）。更大发现：短 D 档（0/30/100）本轮也都触发恢复
（3/4/1 次）且毫秒级兜住 ⇒ **短 D 丢发布是概率性常态**（此前 0/30 "通过"只是没丢，
D=100 的"确定性"是小样本假象），恢复机制常态在线。mb 全套跑完、无空唤醒无 stray。

### B.5 v2：回卷地雷封堵 + 终验闭环（08-23 04:19 轮）

**地雷（三代 v1 复查发现）**：v1 把 read 字段也按缓存快照重写——"干净行误报恢复"
场景（mb 类合法长 op 超软期限，该轮 slot=0/7 各 83 次）快照 read 是 RP 消费前的
陈旧值，重写一旦落地会**回卷 RP 消费进度、制造幻影消息**；该轮恰未显形（疑被 A4
丢失模式本身挡住，不可依赖）。**v2（10efbe1）**：只快照 AP 自有的 write 字段，
read 在 inval 后重读 SRAM 真值——inval 写回滞留脏行或丢弃干净副本两种情况均无
回卷窗口。

**终验**：v2 复跑 fresh_scan 全 8 档 got=1、mb 全程无 stray（幻影判据阴性）；dd
n=30 全 D1：rtt p50 237.7 / mean 238.2（对照 P3 基线 236.9，send 14.6 同环境态系
——启动间漂移规则内统计同形）、**闭环残差 0.0/30**、didx 3.1 保持——看门狗零代价
（测量 30 轮零恢复零扰动；warmup 首轮一次恢复毫秒级兜住，不进测量面）。
**A4 结案**：同核检测证伪 → 纯重发粘滞证伪 → 重写同值破粘滞 → 回卷封堵，全闭环。
产品化收口随 W2 轮询回路软期限。
